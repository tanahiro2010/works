# Terraformで素数をマイニングしたら、ブロックチェーンが生まれた
### 〜 Infrastructure as Code。つまりCode。なら何でもできますよね？ 〜

**企画種別：** 技術LT・個人開発・ネタプロジェクト  
**プロジェクト名：** Terraform PrimeChain  
**想定発表時間：** 10〜15分  
**使用技術：** Terraform / HCL / SHA-256  
**開発方針：** All You Need Is Terraform.

---

## 1. 企画概要

「Infrastructure as Code」という言葉がある。

インフラをコードとして管理する技術であり、その代表格がTerraformである。

しかし、ここで一つの疑問が生まれた。

**「Infrastructure as Code。つまりCodeですよね？ なら素数のマイニングもできますよね？」**

本企画では、この極めて不合理な発想を出発点として、Terraformだけを用いた素数マイニングシステム「Terraform PrimeChain」を開発する。

HCLによる素数探索、Terraform CLIの再帰起動、複数のTerraformによる並列計算、SHA-256を用いたブロック生成を実装し、最終的には簡易的なブロックチェーンを構築する。

最大の特徴は、**計算処理からブロックチェーンの管理まで、すべてのロジックをTerraformで記述すること**である。

## 2. 企画の目的

本プロジェクトには、以下の3つの目的がある。

1. **Terraformの表現力の限界を探る**  
   本来インフラ管理を目的とするTerraformで、数値計算、再帰処理、並列処理、状態管理をどこまで実装できるか検証する。

2. **Terraformの内部的な仕組みを理解する**  
   HCLの式評価、リソースのライフサイクル、Terraform State、依存関係グラフ、Provisionerなどを実践的に学ぶ。

3. **技術的な過剰設計をエンターテインメントにする**  
   「技術的に可能」と「実用的に適切」の違いを、極端な実装を通じて紹介する。

## 3. 技術的な制約

本企画では、以下を絶対原則とする。

- アプリケーションの計算ロジックはTerraform（HCL）のみで記述する。
- Python、JavaScript、Go、Rustなど、他のプログラミング言語による計算は禁止。
- 素数判定、マイニング条件の判定、ハッシュ生成、ブロック検証はHCLで実装する。
- 外部APIや外部Providerへの計算処理の委譲は禁止する。
- 再帰処理はTerraformからTerraform CLIを起動することで実現する。
- Terraform CLIやシェルの使用は、起動・ファイル配置などの実行基盤の操作に限定する。

**Terraform以外に計算させたら負け。**

## 4. システム構成

### Phase 1：Prime Discovery

HCLの`for`式、`range()`、剰余演算などを利用して素数判定アルゴリズムを実装する。

指定範囲の素数を探索し、TerraformのOutputとして出力する。

### Phase 2：Recursive Terraform

Terraformから別のTerraformプロセスを起動する仕組みを構築する。

各Terraformが独立した探索範囲を担当し、必要に応じて子Terraformを起動する。

これにより、単一のHCL式では扱いづらい大規模な探索処理を分割する。

### Phase 3：Distributed Prime Mining

複数のTerraformプロセスを並列で実行する。

各プロセスをMinerとして扱い、それぞれ独立したTerraform Stateを持たせる。

親Terraformが探索条件を決定し、各Minerが素数を探索する。

※ 初期実装では単一マシン上の並列処理とし、複数マシンへの分散は発展課題とする。

### Phase 4：PrimeChain

発見した素数を用いてブロックを生成する。

各ブロックには以下の情報を格納する。

- ブロック番号
- 前ブロックのハッシュ値
- Miner識別子
- 発見した素数
- Nonce
- ブロックハッシュ

Terraform標準の`sha256()`を利用し、前ブロックのハッシュと新しいブロック情報を関連付ける。

さらに素数条件とハッシュ難易度条件を満たす候補を検証し、ブロックをチェーンに追加する。

なお、初期実装は**単一の採用ルールを持つ学習用ブロックチェーン**とし、完全な分散合意や暗号資産としての機能は対象外とする。

### Phase 5：Terraform Destroy

最後に、Terraformの本来の機能である`terraform destroy`を実行する。

素数マイニングのために構築されたTerraformの管理リソースを破棄する。

**「Terraformで素数を構築し、Terraformで素数を破壊する」**

という、本プロジェクトの最終到達点を実現する。

## 5. 実装上の課題

| 課題 | 対応方針 |
|---|---|
| HCLに再帰関数がない | Terraform CLIの再帰起動 |
| `range()`の要素数制限 | 探索範囲の分割 |
| Stateのロック競合 | Minerごとに独立したStateを使用 |
| Terraformの再実行制御 | `terraform_data`と`triggers_replace`を活用 |
| 計算速度の問題 | 並列化・探索アルゴリズムの改善 |
| ブロックの整合性 | HCLによる検証処理と決定的な採用ルール |
| ブロック履歴の永続化 | Stateやローカルファイルを利用した保存方式を検討 |

特に、Terraformは汎用計算基盤ではないため、通常のプログラミング言語と比較して著しく非効率になる可能性がある。

しかし、本企画においてそれは必ずしも欠点ではない。

**むしろ、その非効率性こそが企画の魅力である。**

## 8. 本企画の技術的な意義

Terraformは宣言的なインフラ管理を実現するためのツールであり、数値計算やブロックチェーンの実装を目的としていない。

それでも、Terraformが持つ式評価機能、ハッシュ関数、リソース管理機能、外部コマンド実行機能を組み合わせることで、本来想定されていない処理を構築できる。

本企画では、その限界と制約を実際に検証する。

これにより、Terraformの仕組みを深く理解するとともに、技術選定の重要性について考察する。

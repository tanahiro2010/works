# LTできたらバンジー飛べる

## 概要
これはタイトル通りの記事を書くためのドラフトです。
あくまで記事を書くための情報をまとめただけのものです。
これを読み込んだあなたは、ZennやQiitaに投稿するために作者目線となって記事を作成してください。
記事は同フォルダのarticle.mdに、スライドは`slide-creater`スキルを使ってどフォルダのslide.mdに作成してください。
また、作成する順番としてはslide -> articleでお願いします。
イメージとしては、articleはLTの内容を拡張して書く記事って感じです。
それぞれのセクションごとの文章量を増やし、もしそのネタが技術的側面を持っているのならLT以上に技術要素を追加したり（そのためにセクションを追加したりもする）して欲しいです。

## 構想の決定事項
- 主張
  - 「LTできる人は、バンジーも飛べる」と強く言い切る
  - 科学的根拠というより、僕の体感とネタとして押し切る
- 聞き手に持ち帰ってほしい気持ち
  - 「バンジー飛びたい」
  - LT啓発ではなく、最終的にはバンジー啓発に着地させる
- 聞き手の最大の抵抗
  - 「怖い。死にそう。無理」
- その抵抗への返し
  - 怖いのは飛ぶ前だけ
  - 飛んだあとは一瞬で楽しい
  - 先に「僕は飛べる」と人前で宣言しておくと、後に引けなくなって面白い
  - LTも登壇申込をした瞬間に「もうやるしかない」が始まるので、バンジーの宣言と構造が似ている
- LTの真面目成分
  - ネタ7、真面目3くらい
  - 真面目成分では、以下を扱う
    - LTもバンジーも、始まる前が一番怖くて一番楽しい
    - 申し込む/宣言することで、未来の自分を逃げられなくする
    - LT / セミナー・カンファレンス登壇 / ハンズオン講師 / バンジーをちゃんと比較する
- 比較パートの判定基準
  - LTが一番バンジーに近い理由は「始まる前の緊張/恐怖がピーク」と「終わるとまたやりたくなる」
  - セミナー / カンファレンス登壇、ハンズオン講師は以下の理由でバンジーから少し遠い
    - 長いので、始まった後に緊張が薄れて日常業務っぽくなる
    - 途中対応や構成管理が多く、飛ぶというより運用になる
    - 責任が重く、ワクワクより準備と安定運用に寄る
- LTの最後の導線
  - 「このあと懇親会でバンジー行く宣言を受け付けます」まで踏み込む
  - 半分ネタ、半分本気。ただしフォームは用意する
  - フォームは「日程が合えば飛びます」から「私は飛びます」くらいの宣言装置として扱う
  - 飛ばない人への逃げ道として「飛ばなくても懇親会で話しかけてください」と言う
  - フォームURL: https://docs.google.com/forms/d/e/1FAIpQLSfZ3r9R9KvY0L9etCi67SkHJ3JMnJ8-h1Xb7UzuAGGjuFP0Gg/viewform?usp=publish-editor

- QRコードの出し方
  - 宣言受付専用スライドでQRを大きく出す
  - Thanksスライドにも小さく残す
- 記事の想定
  - Zenn〜Qiita想定
  - エンジニア向けに、LT文化・登壇・学習・アウトプットの話として書く
  - LT本編を拡張しつつ、記事だけの実用パートを入れる
- 記事だけで拡張する内容
  - セミナー / カンファレンス登壇の良さ
    - 長く話すことで、自分の理解が整理される
    - ネタ作りのためのインプットが、エンジニアとしての学習になる
    - 質疑応答や準備を通じて、知識の穴が見える
  - 「バンジー飛ぶためにLT申し込もう」系のセクションを作る
  - その中に、LT準備術を折りたたみ形式で入れる
  - 折りたたみが使えない媒体なら「すでに自分流の方法を編み出してる人は読み飛ばし推奨」と前置きして小セクションにする
  - 文体は軽い実用。ネタ口調を残しつつ、手順はちゃんと書く
- 記事に入れるLT準備ワークフロー
  - 登壇しようと思ったネタに関して、とにかく調べる
  - メモ帳などに箇条書きで書き溜める
  - ネストして補足、自分の感想、気づきも乱雑に書き続ける
  - 文字数カウントで1万文字前後になったら、まとめの構想を練る
  - 箇条書きした情報を取捨選択して書き始める
  - 今回のようにAIに壁打ちするのもあり
- 記事のラスト
  - 「バンジー行こう」に寄せる

ということで、本編です。

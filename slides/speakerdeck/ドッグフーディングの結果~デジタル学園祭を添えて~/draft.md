# ドッグフーディングの結果~デジタル学園祭を添えて~

## 概要
これはタイトル通りの記事を書くためのドラフトです。
あくまで記事を書くための情報をまとめただけのものです。
これを読み込んだあなたは、ZennやQiitaに投稿するために作者目線となって記事を作成してください。
記事は同フォルダのarticle.mdに、スライドは`slide-creater`スキルを使ってどフォルダのslide.mdに作成してください。
また、作成する順番としてはslide -> articleでお願いします。
イメージとしては、articleはLTの内容を拡張して書く記事って感じです。
それぞれのセクションごとの文章量を増やし、もしそのネタが技術的側面を持っているのならLT以上に技術要素を追加したり（そのためにセクションを追加したりもする）して欲しいです。

## LTスライドを作るに当たって
slide-createrスキルを使って、slide.mdを作成してください。
適度に画像を挿入したり、コードを挿入したりして、見やすいスライドを作ってください。
基本的にslide-createrをベースにしつつもデザインはアイテムの中心寄せ・フォントサイズの変更（真ん中にポンと小さいアイテムがあるのを避ける）などを行ってください。
また、他のプロジェクトから画像を持ってくるのもOKです。

## 記事を書くに当たって
記事はスライドの各セクションごとを増量し、そして技術的側面を追加して書くことを意識してください。
また、記事の中では画像を使うことはできません。
marmaidなどで図を作ることはできます。

## 記事・スライド共通ドラフト
- タイトルスライド
  - タイトル: ドッグフーディングの結果~デジタル学園祭を添えて~
  - サブタイトル: 知らないおばちゃんがめっちゃアドバイスくれた話
  - 作者: tanahiro2010
  - 日付: 2026/10/10
- 私が作っているもの
  - ARコミュニュケーション補助システムことE.D.I.T.H(自称)
  - ARスマートグラス付属カメラが相手の顔を認識し、顔の上にネームタグを出してくれたりプロフィールを出してくれたりする便利なやつ
    - のはずが全くスマートグラスの発想通知が来ず、今はパソコンで動く謎のアプリになっている
- 当初は
  - デジタル学園祭に来た人をターゲットにしていた
  - なんか割と仲良くなれて色んな人に試せそうだなと思っていたら...
- 実際は
  - なんか謎のおばちゃん登場！
    - 僕のブースにやけに興味津々にやってくる
- アドバイスの内容
  - 「名前が見えるだけじゃ弱くない？」
  - 「その人のプロフィールとか、どんな人か分かるようにした方がいいんじゃない？」
  - 「てかそもそもパソコンじゃ意味ないぜよ」
  - 「あと――**そのソフト、もっとUX（ユーザー体験）を考えた方がいいんじゃない？**」
- 僕、感銘を受ける
  - 名前さえ見えればいいと思っていたけれど、どうやらそれだけでは不十分だったらしい
  - **体験**――僕がまだ考えたことのなかったアイデアだ
- ということで、UXを考えてみた
  - そもそも「人の名前を覚えられない人」は、本当に名前だけ覚えられないのだろうか？
  - 例えば、こんな経験はないだろうか
    - 「あれ、この人誰だっけ？」
    - 「前に話した気がするけど、何話したっけ？」
    - 「名前は分かるけど、どういう人だったっけ？」
  - そう、名前だけ分かっても、話の内容を覚えていなければ意味がないのでは？
  - **名前を覚えることと、人を覚えることは違う。**

- そもそも会話って覚えられなくない？
  - 皆さん、昨日話した内容を全部覚えていますか？
  - 少なくとも僕は覚えていない
  - そもそも、人って会話中にいちいちメモを取らない
  - というか、普通に会話しながらメモするのって難しくない？
  - だったら、会話の内容も自動で覚えてくれればいいのでは？

- 議事録機能を作り始めた
  - 会話を自動的に記録して、話題ごとに分類する
  - 記録した内容はMarkdown形式で後から確認できる
  - これなら「あの人と何を話したっけ？」を解決できそう
  - ちなみに、現在開発中
    - 分類精度はお察しください
    - 絶賛改善中です
  - ※録音や記録は相手の同意を得た場合のみ

- でも、それだけでは足りない
  - 例えば、久しぶりに会った人の名前を思い出したいとする
  - そもそも、その人を登録したかどうか覚えていない
  - というか、登録した人を一覧で見られないのは不便では？
  - **あれ、これもUXの問題では？**

- 名前一覧機能も作り始めた
  - 登録した人の情報を後から一覧で確認できるようにする
  - プロフィールや過去の会話記録も一緒に確認できるようにしたい
  - これなら、会話する前に相手の情報を思い出せる
  - ただし、問題がひとつ
    - まだアカウント機能がない
    - 現状、他の利用者の登録情報まで見えてしまう
    - さすがにこれは公開できない
  - ということで、認証・アクセス制御も実装予定

- ここで気づいたこと
  - 最初は、ARで名前が見えれば便利だと思っていた
  - でも、実際に使う場面を考えてみると、それだけでは不十分だった
  - 名前が分かっても、相手のことを知らなければ会話は続かない
  - 話の内容が分かっても、必要なときに思い出せなければ意味がない
  - **「情報を表示すること」と「コミュニケーションを助けること」は違う。**

- E.D.I.T.Hは何を目指すのか
  - 当初の目標
    - 顔を認識する
    - 名前を表示する
    - おしまい
  - 現在の目標
    - 相手が誰なのか分かる
    - どんな人なのか分かる
    - 過去に何を話したのか分かる
    - 次の会話につなげられる
  - **人を覚えるためのツールから、人とのつながりを支えるツールへ。**

- とはいえ、まだまだ課題は山積み
  - スマートグラスが届かない
  - 議事録機能の精度が低い
  - アカウント機能がない
  - 個人情報の管理をどうするか
  - そもそも、本当に使いやすいのか？
  - というか、まだスマートグラスで動いてすらいない

- 今回の学び
  - 自分が便利だと思う機能と、ユーザーが必要とする機能は違う
  - 開発者はどうしても「何を実装するか」を考えがち
  - でも、本当に重要なのは「ユーザーがどう使うか」
  - **UXとは、画面の使いやすさだけではなく、使う前後も含めた体験そのもの。**

- 最後に
  - 今回、デジタル学園祭で出会ったおばちゃんのおかげで、
    E.D.I.T.Hの方向性は大きく変わった
  - 正直、最初は名前が表示されれば完成だと思っていた
  - でも、実際に他人の視点を取り入れてみると、
    自分では気づけなかった課題が次々と見つかった
  - **自分の作ったものを、自分だけで評価してはいけない。**
  - そして――
  - **ありがとう、名も知らぬおばちゃん。**

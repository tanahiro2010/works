## 2. 用語集

### 聴衆に伝わらないかもしれない言葉（その場での一言説明つき）

| 用語                             | 一言で言うと                                                  | 補足（聞かれたら）                                                                               |
| -------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Terraform**                    | インフラを設定ファイルで管理するツール                        | HashiCorp 製。「このサーバーを 3 台」と書いて `apply` すると、実際のクラウドをその状態に合わせる |
| **HCL**                          | Terraform の設定ファイルを書く言語                            | HashiCorp Configuration Language。JSON に式と関数が付いたもの。**手続き的なループも再帰もない**  |
| **IaC / Infrastructure as Code** | インフラをコードとして管理する考え方                          | 手作業でコンソールをポチポチせず、コードにして Git 管理・レビュー・再現できるようにする          |
| **`terraform apply`**            | 書いた状態を実際に反映するコマンド                            | 今回は反映するものが何もないので、ただの式評価エンジンとして使っている                           |
| **`terraform plan`**             | 反映前に差分を計算するコマンド                                | 今回の改ざん検知はここで止まるのがミソ                                                           |
| **`terraform destroy`**          | 作ったものを全部消すコマンド                                  | Phase 5 で使う本来の機能                                                                         |
| **State / `terraform.tfstate`**  | Terraform が「今こうなっているはず」を記録する JSON           | 実体はただのファイル。**今回のハマりポイントはほぼ全部これ絡み**                                 |
| **State ロック**                 | 同時に 2 つの Terraform が State を触らないための排他制御     | Phase 2 で、子の init が親のロックとぶつかった                                                   |
| **backend**                      | State をどこに置くかの設定                                    | `local` ならローカルファイル。今回はこれで State の置き場所をずらして衝突を回避した              |
| **Provider**                     | AWS や GCP など、操作対象ごとのプラグイン                     | 今回は外部 Provider を一切使わない（= 計算を外注しない）のがルール                               |
| **`terraform_data`**             | 何も作らない組み込みリソース                                  | 「リソースのライフサイクルだけ欲しい」ときに使う公式の仕組み。今回のブロックはこれ               |
| **`local-exec` provisioner**     | リソース作成時にローカルでコマンドを実行する機能              | 本来は非推奨寄りの最終手段。今回は Terraform を起動するためだけに使う                            |
| **`terraform_remote_state`**     | 他の Terraform の State から Output を読むデータソース        | 本来はチーム間で VPC ID などを共有する用途。今回は**子プロセスの戻り値**として使っている         |
| **`for` 式**                     | HCL のリスト内包表記                                          | `[for n in list : n if 条件]`。ループがない HCL で唯一の繰り返し手段                             |
| **`alltrue()`**                  | 真偽値リストが全部 true か判定する関数                        | 素数判定の「どの数でも割り切れない」がこれ 1 つで書ける                                          |
| **`precondition`**               | リソース作成前に満たすべき条件を書く仕組み                    | 満たさないと plan / apply が止まる。今回はブロック検証に使った                                   |
| **`for_each`**                   | 1 つの定義から複数リソースを作る仕組み                        | Miner やブロックの複製に使用                                                                     |
| **`TF_VAR_*`**                   | Terraform の変数を環境変数で渡す仕組み                        | 子プロセスへの**引数渡し**に使っている                                                           |
| **並列度 10**                    | Terraform がデフォルトでリソースを 10 個まで同時に作ること    | `-parallelism` で変更可能。Miner が勝手に並列になる理由                                          |
| **素数 / 試し割り法**            | 1 と自分自身でしか割れない数 / 2〜√n で順に割って確かめる方法 | √n まででいいのは、n = a×b なら小さいほうは必ず √n 以下だから                                    |
| **ブロックチェーン**             | ブロックを前のブロックのハッシュでつないだ台帳                | 途中を書き換えるとハッシュが合わなくなるので改ざんが分かる                                       |
| **ハッシュ / SHA-256**           | 入力から 64 文字の文字列を作る一方向の関数                    | 少しでも入力が変わると全然違う値になる。Terraform に `sha256()` が組み込まれている               |
| **Nonce**                        | ハッシュ条件を満たすために変える使い捨ての数値                | 「ブロックの中身は変えずにハッシュだけ変える」ためのダイヤル                                     |
| **Proof of Work (PoW)**          | ハッシュが条件を満たすまで計算を繰り返す仕組み                | 今回の条件は「先頭が `00`」。難易度 = 先頭に必要な 0 の数                                        |
| **難易度 (difficulty)**          | 必要な先頭 0 の個数                                           | 今回はデフォルト 2。上げると指数的に時間が増える                                                 |
| **ジェネシスブロック**           | チェーンの最初のブロック                                      | 前のハッシュが存在しないので 0 を 64 個並べたものを使う                                          |
| **台帳 / ledger**                | チェーン全体の記録                                            | 今回は `ledger.json`                                                                             |
| **Miner**                        | 採掘する人（プロセス）                                        | 今回は Terraform プロセス 1 個 = Miner 1 人                                                      |

### 言い換えメモ（インフラ勢以外が多い会場向け）

- 「State」→「Terraform のセーブデータ」
- 「`terraform apply`」→「実行ボタン」
- 「Provider」→「接続プラグイン」
- 「`local-exec`」→「シェルを呼ぶ抜け道」
- 「Nonce」→「ハッシュガチャの回数券」

## 3. 想定QA

### 企画そのものへの質問

**Q. なぜ Terraform なんですか。Python でよくないですか。**
**A. Python なら一瞬で終わります。** それは本当にそう。ただ「Infrastructure as Code の Code の部分ってどこまで Code なんだろう」が出発点だったので、Terraform じゃないと意味がなかったです。結果として、State や init の挙動を普段の業務より深く知ることになったので、学習効果はかなり高かったです。

**Q. なぜ素数なんですか。**
**A. HCL だけで完結して、かつ正しさが自明に検証できる計算だからです。** 素数判定は for 式と剰余演算だけで書けて、外部ライブラリも浮動小数点の誤差もいらない。さらに「掘る（マイニング）」という言葉がブロックチェーンに素直につながったので、Phase 4 に発展させられました。

**Q. これ、実用性はありますか。**
**A. ありません。** ただ副産物として、`local-exec` + `TF_VAR_*` + `terraform_remote_state` で Terraform をプロセス間通信させるパターンは、モジュールを動的に分割したいときに応用が効くと思います。あと `precondition` で不変条件を plan 時に検証するのは、普通に実務で使えるテクニックです。

**Q. どのくらいの期間で作りましたか。**
**A.** 〈実績に合わせて回答。ハマった時間の内訳（State ロック / panic）を話すと盛り上がる〉

### 実装への質問

**Q. `range()` の 1024 制限ってなんでそんな仕様なんですか。**
**A. HCL が巨大なリストを式評価でうっかり作らないようにするガードです。** 設定ファイルの言語なので、メモリを食いつぶす設定を書けないようにしてある。今回みたいに計算基盤として使うと真っ先にぶつかります。回避策は範囲を 1024 ずつのチャンクに割って `flatten` すること。ただし割る側の `range(2, √n)` も 1024 以内なので、扱える上限は 1024² = 1,048,576 です。

**Q. 100 万より上の素数はどうするんですか。**
**A. 試し割りをやめて、除数側もチャンク分割すれば原理的には伸ばせます。** ただ HCL の式評価は全候補をメモリに展開するので、現実的には先に別の壁が来ます。素直にやるなら Phase 2 の再帰で範囲を細かく切って、プロセス数で殴ることになります。

**Q. なぜ再帰で半分に割るんですか。Pool みたいに最初から N 分割じゃだめ？**
**A. 結論としては Pool のほうが速いです。** Phase 2 は「HCL に再帰がないなら Terraform 自体を再帰させればいい」というのをやりたかったパートで、実利は Phase 3 で回収しています。ただ再帰のほうが「範囲の大きさに応じて勝手に分割粒度が決まる」ので、探索範囲が事前に分からないケースには向いています。

**Q. 子の Terraform が失敗したらどうなりますか。**
**A. `local-exec` が非ゼロ終了するので、親の apply も失敗します。** 子のログの末尾 30 行を親の出力に出すようにしてあるので、どの子が落ちたかは分かります。ただしリトライ機構はないので、`triggers_replace` が変わらない限り再実行はされません。

**Q. State ロックの問題、`-lock=false` で回避しなかったんですか。**
**A. それでも動きますが、根本原因が「子の init が親の State を移行しようとする」ことなので、State の置き場所を分けるほうが正しい対処です。** ロックを切ると今度は本当に同時書き込みが起きる構成になるので、そこは避けました。

**Q. 並列度を 10 より上げたら速くなりますか。**
**A. ある程度は。** `-parallelism` で増やせますが、Miner 1 つが Terraform プロセス 1 つなので、コア数を超えると普通に頭打ちになります。今回の 8 Miner で 3.2 倍というのも、プロセス起動と init のオーバーヘッドが効いていて線形には伸びていません。

**Q. `terraform_data` って何ですか。`null_resource` とは違う？**
**A. ほぼ同じ用途の、Provider 不要な組み込み版です。** `null_resource` は `null` provider が必要ですが、`terraform_data` は Terraform 1.4 から組み込みで使えます。今回は「外部 Provider を使わない」ルールがあるので `terraform_data` 一択でした。`input` に値を持てるので、ブロックの中身を State に残すのにも都合がよかったです。

**Q. `apply` 中に State を読んで panic したという話、バグでは？**
**A. 使い方が想定外なので、報告はしていません。** 自分の State を自分の設定内から `file()` で読むというのは完全に想定外の使い方で、エラーメッセージが panic になっているのは行儀が悪いものの、そもそもやるべきことではないので台帳はファイルに逃がしました。

### ブロックチェーンへの質問

**Q. これ、ブロックチェーンと呼んでいいんですか。**
**A. 「ハッシュで連結された、検証可能な台帳」という意味では満たしています。** ただし分散合意は入っていません。Miner は並列に候補を出しますが、採用するのは親が「ハッシュ最小」という決定的なルールで選ぶので、フォークも最長鎖ルールもありません。そこは学習用と割り切っています。

**Q. なぜ採用ルールが「ハッシュ最小」なんですか。早い者勝ちじゃないのは？**
**A. Terraform が何度 plan しても同じ結果でないと壊れるからです。** 早い者勝ちにすると実行のたびに結果が変わって、plan と apply で別のブロックになります。決定的なルールが必要だったので、全候補を集めてからハッシュ辞書順で最小のものを選んでいます。

**Q. 素数は Proof of Work に関係しているんですか。**
**A. 間接的にです。** ブロックに入れられる素数は「その範囲で実際に見つかった素数」だけなので、素数探索そのものが参加条件になっています。その上で素数 × nonce の組み合わせからハッシュ条件を満たすものを探すので、PoW 部分は普通の sha256 総当たりです。

**Q. 改ざん検知はどこまで効きますか。**
**A. 台帳の中身を書き換えたら plan で止まります。** ブロック番号の連番、前ハッシュとの連結、ハッシュの再計算、難易度条件、そして素数であることの 5 つを全ブロックに対して毎回検証しているので、どれか 1 つでも崩れると `precondition` で落ちます。逆に、ledger.json を丸ごと消せばジェネシスからやり直しになります。そこは守っていません。

**Q. 難易度を上げたらどうなりますか。**
**A. 指数的に時間が増えます。** 今回はデフォルトで先頭 `00`、素数 1 つあたり nonce を 64 個試す設定です。難易度を 3 にすると、現実的な時間で掘れるようにするには `max_nonce` か探索範囲をかなり増やす必要があります。HCL は全組み合わせを一度にメモリ展開するので、そこでも制限にぶつかります。

### ルールまわりの質問

**Q. シェルスクリプト使ってるじゃないですか。それはルール違反では？**
**A. シェルがやっているのは「ディレクトリを掘る」「terraform を起動する」「HCL が作った文字列をファイルに書く」だけです。** 計算は一切していません。`ledger.json` の中身も HCL の `jsonencode` が作ったもので、シェルは `printf` でリダイレクトしているだけです。`jq` を使っているのは改ざんデモのところだけで、あれは攻撃者側なのでセーフとしています。

**Q. Makefile はどうなんですか。**
**A. 実行基盤の操作だけです。** `make prime` は `terraform apply` に変数を渡しているだけ、`make mine` はブロック数だけループして `apply` を繰り返しているだけです。素数もハッシュも Makefile では計算していません。

**Q. `sha256()` は Terraform の組み込みだからセーフなんですか。**
**A. セーフとしました。** 組み込み関数は HCL の式評価の一部なので、外部に計算を委譲していないという整理です。ここを禁止すると HCL だけで SHA-256 を実装することになり、`range()` の 1024 制限で詰みます。

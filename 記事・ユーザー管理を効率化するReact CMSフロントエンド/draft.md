# 記事・ユーザー管理を効率化するReact CMSフロントエンド

## 概要
これはタイトル通りの記事を書くためのドラフトです。
あくまで記事を書くための情報をまとめただけのものです。
これを読み込んだあなたは、ZennやQiitaに投稿するために作者目線となって記事を作成してください。
記事は同フォルダのarticle.mdに、スライドは`slide-creater`スキルを使ってどフォルダのslide.mdに作成してください。
また、作成する順番としてはslide -> articleでお願いします。
イメージとしては、articleはLTの内容を拡張して書く記事って感じです。
それぞれのセクションごとの文章量を増やし、もしそのネタが技術的側面を持っているのならLT以上に技術要素を追加したり（そのためにセクションを追加したりもする）して欲しいです。
また、実際に作ったコードや画像を使うこともできます。

## LTスライドを作るに当たって
slide-createrスキルを使って、slide.mdを作成してください。
適度に画像を挿入したり、コードを挿入したりして、見やすいスライドを作ってください。
また、他のプロジェクトから画像を持ってくるのもOKです。

## 記事を書くに当たって
記事はスライドの各セクションごとを増量し、そして技術的側面を追加して書くことを意識してください。
また、記事の中では画像を使うことはできません。
marmaidなどで図を作ることはできます。

## 記事・スライド共通ドラフト
フェンリル株式会社インターンシップ2026のフロントエンドチームに参加。
React SPA + Tanstack Routerを使ってSNS管理者向けサイトのフロントエンドを開発。
CSSやUIコンポーネントの設計などは仕様書に沿う機能が作れるならなんでも使ってOK。
なので私はTailwindCSSを使って開発。

気をつけたこと
- APIの呼び出し処理を毎度書くのではなく、cmsクライアントを作ってライブラリ的に使えるようにすること
  - cms.auth.login()やcms.article.getArticles()などのように、APIの呼び出しを簡単にすること
- 似たデザイン、似た機能が多いので、コンポーネントの再利用性を意識して作ること
- Tanstack Routerのloadersを使って、データの取得を効率化すること
- 副作用についてあまりわかっていないので、useEffectはなるべく使わないようにすること



作ったもの
管理者向けCMSのフロントエンド
記事一覧、記事詳細、ユーザー一覧、ユーザー詳細を実装
検索・ソート・ページネーションで大量データを扱いやすくした

デモの流れ
ログイン後、記事一覧を見る
検索して記事を絞る
リスト表示/カード表示を切り替える
記事詳細で公開/非公開を切り替える
ユーザー一覧でユーザーを探す
ユーザー詳細で凍結/解除、投稿記事を確認する

工夫した点
TanStack Router の loader でページ表示前にAPIデータを取得
useArticleSort / useUserSort でソート処理を分離
Pagination, SearchInput, SortDropdown, Button などを共通コンポーネント化
401エラー時はトークンを消してログインへ戻す処理を入れている
記事カード表示では画像、いいね数、投稿日時、公開状態が直感的に見える
